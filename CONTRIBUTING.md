# Contributing to the GreenStar Homes standard

The standard is maintained by the GreenHome Institute. This repository is the
open text of the standard; changes accepted here are ratified by the Institute
and incorporated into the next published version of the manual.

## Flag a problem
Open an issue. Useful issues name the requirement (file + heading) and say what
is wrong, unclear, outdated, or missing — citations to codes, studies, or field
experience make them stronger.

## Substantive changes: write an RFC
Changes that move the certifiable bar — new requirements, changed thresholds,
level changes — start as an RFC rather than a direct edit. See
[rfcs/README.md](rfcs/README.md). Health/safety errors in the published text
get a fast track instead: see [ERRATA.md](ERRATA.md).

## Propose a change
1. Fork this repository.
2. Edit the relevant file under `standard/` (or `levels.md` / `badges.md`).
3. Open a pull request explaining the reasoning: what changes, why, and what
   evidence supports it.

Practitioner experience counts as evidence — raters, inspectors, builders, and
homeowners see how requirements behave in the field.

## What happens to merged changes
The Institute's source of truth is its content system; maintainers apply
accepted changes there, which republishes the site, the JSON, and this repo.
A change is part of the certifiable standard only when the Institute publishes
it in a versioned manual release.

## Licensing of contributions
By opening a pull request you affirm the contribution is your own work (or
properly attributed) and that you license it under CC BY-SA 4.0, the same
license as the rest of the standard. This keeps the standard cleanly
reusable for everyone.

## Ground rules
Be specific, be kind, argue from building science. The Institute has final say
over what enters the certifiable standard.
